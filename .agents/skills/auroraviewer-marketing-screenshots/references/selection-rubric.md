# Screenshot image selection rubric

Use this rubric after visually surveying the sample pool. It guides judgment; it is not a mechanical scoring formula.

## Shared filters

Reject a candidate before aesthetic scoring when it is unsuitable for a public product website, especially when it contains private documents, account information, readable personal identifiers, intimate/private scenes, or other sensitive material.

Prefer source images that are technically clean enough to survive a large Retina screenshot: adequate resolution, no accidental corruption, and no distracting watermark unless the watermark is intentionally part of the public asset.

Across the final set, aim for visual continuity without monotony. A useful set usually shares a compatible overall quality and mood while varying subject, color, and function.

## Viewer / hero

Prioritize:

1. immediate visual appeal at first glance
2. clear composition when fitted inside a landscape app window
3. enough detail to make zoom/minimap/viewer UI feel useful
4. color and tonal range that complement AuroraViewer's restrained site palette
5. low visual clutter near important UI overlays
6. broad, neutral suitability for a software product homepage

Avoid extremely narrow panoramas, tiny subjects surrounded by empty space, screenshots of other software, dense text imagery, or compositions that only work when heavily cropped.

## Library / thumbnail

Judge the visible group, not only the active image.

Prioritize:

1. a thumbnail region with enough files to make library scale obvious
2. visual variety across subject, orientation, hue, and brightness
3. a collection that still feels intentional rather than chaotic
4. an active image that works as a larger preview
5. filenames/thumbnails that do not expose sensitive information

When the directory is enormous, choose the best scroll region rather than assuming the first items are representative.

## Compare

Prioritize relationship between images over standalone beauty.

Strong pairs include:

- same subject with exposure/color/edit differences
- burst or adjacent captures with pose/timing differences
- near-duplicate compositions
- same location/scene with meaningful framing differences
- related graphical/render variants where visual comparison is obvious

The pair should make a visitor understand why synchronized comparison is useful within a second or two.

Reject pairs that are merely two attractive but unrelated images.

## Color Inspector

Prioritize:

1. multiple distinct hues
2. smooth gradients plus hard edges or fine texture
3. local regions where a magnified pixel grid is informative
4. enough contrast for inspector text/chrome to remain legible
5. a sampling point that tells a visual story (for example a saturated highlight, textured material, foliage, sky transition, or colored object edge)

Avoid nearly monochrome or flat images unless they contain exceptionally useful tonal detail.

## Tie-breaking

When multiple candidates are equally strong:

1. choose the candidate that best complements the other screenshot roles
2. choose the one with fewer privacy/publication concerns
3. choose the one that needs less UI/crop manipulation
4. prefer a candidate whose natural aspect and composition fit the AuroraViewer window
5. prefer visual diversity over reusing the same hero image everywhere

## Final set review

Before publishing, view all four final captures together at thumbnail size and ask:

- Does the set feel like one real current version of AuroraViewer?
- Does each screenshot demonstrate a different user value?
- Is the hero the strongest first impression?
- Is Compare an obviously related comparison?
- Is Color Inspector visually self-explanatory?
- Does Library communicate scale rather than clutter?
- Would any image create privacy or licensing concern if the site became public today?

If any answer is no, revisit the shortlist rather than patching the weakness with decorative web design.
